# Lesliea_AndroidNote

适用于安卓 ColorOS 平板端的手写笔记软件。面向大屏设备深度优化：真实压感笔迹、1000% 连续缩放下零延迟零撕裂的墨水渲染、多标签编辑、资料库管理与文档导入导出。

> 当前版本：v3.2.11（versionCode 78）· minSdk 28 / targetSdk 34 · 适配 OPPO Pad（OPD2101）

## 核心特性

### 书写体验
- **5 种笔刷**：钢笔、书法笔、圆珠笔、铅笔（HB）、荧光笔，均支持宽度 / 不透明度 / 压感 / 速度感应 / 倾斜感应独立调节
- **压感与防误触**：手写笔优先，落笔后自动忽略手掌误触；无压感设备模拟压力
- **1000% 连续缩放**：双指捏合缩放/平移，顶部实时蓝色缩放指示器（停止操作自动隐藏），右上角一键回到整页视图
- **运动预测**：MotionPredictor 预测笔尖轨迹，降低输入到显示的跟随延迟

### 墨水渲染管线（本项目的技术核心）
- **实时墨迹**：Catmull-Rom 样条细分 + 变宽三角带网格，逐点增量构建（O(1)/点）
- **矢高覆盖圆盘**：弯曲段按“弧长 ÷ 线宽”自适应发射覆盖圆盘，任何线宽、任何缩放下笔迹实心连续无撕裂
- **笔尖细分条**：最新一段样条细分 + 逐区间圆盘，笔尖实时贴合曲线
- **O(1) 帧渲染**：已确认笔画增量烘焙进位图，每帧只做位图 blit + 笔尖小段绘制——书写成本与笔画长度无关
- **收笔重网格化落定**：收笔时从页面坐标几何按落定图层比例重网格化，墨水与缩放无关（v3.2.5 起不再直接变换拷贝屏幕分辨率烘焙位图，避免深缩放时细笔迹在落定层被压没）
- **1000% 实测**：任意笔刷、任意线宽下 P50 ≈ 6ms，无卡顿帧

## 已知问题排查手册（再出问题先看这里）

> 墨水渲染一直是本项目最常返修的领域。下面把**撕裂感**与**延迟/卡顿**两类问题的根因、判断方法和修复手段固化下来。遇到同类现象时按此定位即可，避免重新考古。

### 1. 笔迹撕裂 / 白色裂缝（细线钢笔最明显）

**症状**：钢笔调到最小线宽（1.13pt）书写时，笔迹在**拐弯处**出现白色裂缝/撕裂；粗笔几乎看不见。

**根因**：笔迹由一串变宽四边形（quad）拼接，拐点处前后段方向（法线）不同，只在**外侧**补一块三角楔（bevel），**内侧**留出月牙形空缝。缝是固定宽度量，笔越细相对越明显——所以只有细线钢笔最敏感。

**先判断是哪一层**（两条独立渲染路径，互不共用）：
- 书写过程中就裂 → **实时层**
- 写完后 / 平移后才裂 → **提交层**

**修复手段**：在拐角 `JOIN_TRIANGLE` 分支补一个 knot 圆盘，盖住内侧缺口（外轮廓不变）：
- 提交层：`core-render/.../PageRenderer.java` 的 `buildRoundUnionPath`（v3.2.10 修复）
- 实时层：`core-render/.../InkView.java` 的 `appendStableQuad`（v3.2.11 修复）

**再出现时**：先确认在哪一层裂，再检查该层 `JOIN_TRIANGLE` 分支是否漏了 `addRoundDisc`（圆盘半径 = 该点宽度一半，`Path.Direction.CCW` 与四边形同向，保证非零环绕求并）。

### 2. 书写延迟 / 卡顿

按四种典型场景分治，各有独立机制：

**A. 笔画越长越卡（整笔重绘）**
- 根因：每帧重画整根笔迹的累计 Path。
- 机制：**增量渲染 + 位图烘焙**。新段逐点 append，已画段烘焙进屏幕位图（liveBaked），每帧只做位图 blit + 笔尖小段，成本与笔画长度无关（O(1)）。
- 再出现：检查是否又把已提交段重复 rasterize。

**B. 深缩放（1000%）书写卡顿**
- 根因：视口缩放直接进曲线细分，一个硬件采样点炸成上百面，再逐帧重建大 Path。
- 机制：`core-ink/.../LiveInkQualityPolicy` 按缩放级别封顶细分预算，快写/慢写分档；已烘焙段的重绘也按同预算处理。
- 再出现：检查 `tessellationScale` 是否又直接取了 viewport scale（应该封顶）。

**C. 细线快写跟不上（连笔断/延迟）**
- 根因：覆盖圆盘按“段数”发射，细笔一段打几十上百个盘，盘数随笔宽成反比爆炸。
- 机制：矢高覆盖圆盘改为**“弧长 ÷ 线宽”自适应**（v3.2.0）——只在实际弯曲且矢高超阈值的段补盘，盘间距随宽度，细笔少而精。
- 再出现：看 cover disc 数量是否又随笔宽反比爆炸。

**D. 1000% 写完平移卡顿 / 笔迹变化**
- 根因：视窗位图每次 new/free（GC）、全页笔迹重网格化、防抖过长、笔锋只在提交后出现。
- 机制（v3.2.7–3.2.9）：视窗**全设备分辨率**（64MB 上限 + 分辨率优先策略）；**窗口位图复用** + **只重网格化窗口内笔迹** + 平移 8ms / 缩放 80ms 防抖；**pen-up 提交改按提交网格重网格化**（笔锋抬笔即现，平移不再突变）。
- 再出现：分别检查上述四个点是否被回退。

### 3. 附：深缩放渲染的三个硬约束（改渲染逻辑前先读）

- 提交笔迹**必须**从页面坐标几何按落定图层比例重网格化，**绝不** blit 屏幕分辨率烘焙位图，否则墨水随缩放漂移/消失。
- 所有曲线段都要补覆盖圆盘（直线段不需要），否则宽铅笔/荧光笔出现细裂纹。
- 高倍放大笔迹断层/白三角的根因是**轮廓自相交 + 宽笔法线翻转**——优先用“矢高覆盖中点圆盘”而非加大细分密度。

## 笔记与文档
- **多标签编辑**：同时打开多个页面，横竖屏自适应
- **资料库**：分区（全部笔记 / 最近 / 收藏 / 标签 / 文件夹 / 回收站）、可折叠侧栏、全文搜索（含手写 OCR）
- **导入**：PDF、Office 文档、CAJ、扫描文档、图片
- **导出**：PDF / 图片分享
- **音频笔记**：录音与笔记联动
- **安全**：笔记加密存储（core-security）

## 模块结构

```
project/
├── app/                  # 应用壳：导航、主题、组装
├── core/
│   ├── common/           # 通用工具

│   ├── ink/              # 墨水引擎：平滑、样条细分、笔刷网格
│   ├── render/           # 渲染：视口变换、墨水视图、页面渲染
│   ├── search/           # 搜索
│   └── security/         # 加密
├── feature/
│   ├── library/          # 资料库
│   ├── editor/           # 编辑器（笔刷栏、缩放指示器、整页按钮）
│   ├── import/ export/   # 文档导入导出
│   ├── audio/            # 音频笔记
│   ├── ocr/ handwriting/ # OCR 与手写识别
│   └── search/ settings/ # 搜索与设置
└── document/
    ├── pdf/ office/ caj/ # 文档解析
```

## 构建

```bash
# 环境要求：JDK 17、Android SDK（compileSdk 34）、Gradle 8.9
cd project
./gradlew assembleRelease      # Release APK（需 keystore.properties 配签名）
./gradlew assembleDebug        # Debug APK
./gradlew test                 # 单元测试（core-ink / core-render 全量）
```

`local.properties`、`keystore.properties`（签名配置）不入库，需自行创建。
